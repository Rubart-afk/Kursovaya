# Архив событий почтового сервера

Курсовой проект по дисциплине «Основы программирования и алгоритмизации».

**Индивидуальный вариант: 11. Почтовый сервер. Уровень: 1 — базовый.**

## Назначение проекта

Программа на языке C предназначена для обработки текстовых сообщений о работе почтового сервера. Каждое сообщение преобразуется в запись структуры Event. Записи накапливаются в оперативном буфере, а при выполнении регламента обрабатываются и записываются в архивный файл.

## Условия индивидуального варианта

- Формат сообщения: `час:минута node messages errors`.
- Структура Event: `h, m, node, messages, errors` — не более пяти полей.
- Регламент архивации: через 60 минут **и** при наличии не менее 30 записей.
- Запись считается дубликатом, если совпадают все поля, кроме времени.
- Дополнительный поиск не требуется.
- Дополнительная сортировка не требуется.
- Необходимо вывести количество полученных, отброшенных как дубликаты и записанных в архив записей.

## Входные данные

Пример строки:

```text
10:15 3 120 2
```

| Поле | Назначение |
|---|---|
| h | Часы |
| m | Минуты |
| node | Идентификатор узла |
| messages | Числовой показатель количества сообщений |
| errors | Числовой показатель количества ошибок |

Период, к которому относятся показатели messages и errors, в задании не уточнён. Программа должна обрабатывать переданные значения без предположений об их накопительном характере.

## Правила обработки

1. Прочитать строку и разобрать поля с помощью scanf или sscanf.
2. Проверить корректность данных.
3. Добавить запись в массив структур.
4. Проверить одновременное выполнение двух условий: прошло не менее 60 минут и накоплено не менее 30 записей.
5. При выполнении регламента удалить дубликаты из накопленного набора.
6. Записать обработанные записи в файл.
7. После успешной записи очистить оперативный буфер и начать следующий период.

Временной интервал определяется по временным меткам сообщений, а не ожиданием реального времени. Порог количества проверяется до удаления дубликатов.

Например, записи `10:15 3 120 2` и `10:40 3 120 2` считаются дубликатами. Запись `10:45 3 121 2` отличается показателем messages и дубликатом этих записей не является.

## Уточнённые правила обработки

Ниже зафиксированы проектные решения для вопросов, которые не раскрыты в индивидуальном варианте. Это принятые ограничения программы, а не дополнительные требования преподавателя.

### Формат и проверка данных

- Входной поток — текстовый файл: одно событие на строку.
- Поля h и m — целые числа: часы от 0 до 23, минуты от 0 до 59.
- Поля node, messages и errors — целые числа от 0 до 2147483647. Узел с номером 0 допустим: вариант не задаёт нумерацию узлов.
- Отрицательные числа, дроби, отсутствующие поля, лишние данные и числа вне диапазона считаются ошибкой.
- Между числовыми полями допустимы пробелы и табуляция, вокруг строки — пробельные символы. Между часами и минутами стоит двоеточие.
- Максимальная длина строки — 255 символов без окончания строки. Более длинная строка целиком отклоняется, её остаток не считается новым сообщением.
- Пустые строки пропускаются. Некорректная непустая строка учитывается как ошибочная; выводится её номер и причина, затем чтение продолжается.
- Ошибочная строка не попадает в буфер и не изменяет временное состояние программы. Саму ошибку чтения файла следует отличать от конца файла и считать причиной аварийного завершения.
- Неверно сформированные и слишком большие числа должны отклоняться до небезопасного числового преобразования. Одной проверки количества присваиваний sscanf недостаточно для проверки диапазона.

### Время и момент архивации

Входной файл считается хронологически упорядоченным. Между соседними корректными событиями проходит менее 24 часов; пропущенные целые сутки не поддерживаются, поскольку в сообщении нет даты.

Время переводится в минуты: 60 × h + m. Уменьшение времени относительно предыдущего корректного события означает переход на следующие сутки; к абсолютному времени добавляются 1440 минут. Одинаковые временные метки допустимы и соответствуют одному моменту времени.

Например, от 23:30 до 00:30 проходит 60 минут. Последовательность 10:20 → 10:10 будет истолкована как следующий день. Отличить её от ошибочного порядка сообщений по имеющимся полям невозможно. Проверка произвольного нарушения хронологии не заявляется.

Интервал текущей порции отсчитывается от её первой записи до только что добавленной записи. Сначала событие добавляется в буфер, затем проверяются оба условия:

- интервал не менее 60 минут;
- количество записей в буфере не менее 30.

Запись, на которой сработал регламент, входит в обрабатываемую порцию. Дубликаты тоже входят в пороговые 30 записей. Даже если после фильтрации осталась одна запись, порция может быть архивирована.

После успешной записи порции буфер очищается. Отсчёт следующей порции начинается с первого нового события; общий счёт переходов суток сохраняется. Реальные таймеры и ожидание часа не используются.

### Дубликаты

Две записи считаются одинаковыми только при совпадении node, messages и errors. Поля времени в сравнении не участвуют.

Удаление выполняется внутри текущей порции. Сохраняется первая встретившаяся запись с её исходным временем; остальные совпадения отбрасываются. Порядок оставшихся записей сохраняется. Сравнение с уже записанными порциями и с содержимым старого архивного файла не выполняется.

### Размер буфера и завершение ввода

Проектная вместимость буфера — 1000 записей, задаваемая константой MAX_EVENTS. Это выбранный предел реализации, а не число из задания.

Заполнение буфера само по себе не является основанием архивации. Если после добавления тысячной записи оба условия выполнены, порция обрабатывается обычным образом.

Если буфер уже содержит 1000 записей и очередное корректное событие добавить невозможно, обработка прекращается с ошибкой. Новое событие не записывается за границами массива и не заменяет старое. Накопленная порция не архивируется принудительно. В диагностике указываются число незаписанных событий и номер непринятой строки. Для такого входного файла требуется пересмотреть вместимость и повторить запуск; автоматическое продолжение после переполнения не предусмотрено.

При обычном конце файла:

- пустой буфер не обрабатывается;
- непустой буфер, не выполнивший регламент, не записывается в архив;
- программа сообщает количество оставшихся неархивированных записей.

Остаток не сохраняется между запусками. Исходный файл остаётся источником данных для повторной обработки. Это ограничение должно быть явно показано пользователю.

### Архивный файл и статистика

Обработанные порции дописываются в один текстовый файл в порядке поступления. Каждая строка имеет формат HH:MM node messages errors; служебные заголовки и статистика в файл не включаются. Дата в архив не добавляется: Event сохраняет пять полей варианта.

При повторном запуске с тем же входом записи будут добавлены повторно: межзапусковая фильтрация не предусмотрена. Для независимых контрольных проверок используется новый пустой архивный файл.

Если порций нет, существующий архив остаётся неизменным; создавать пустой архив необязательно. Исходный и архивный файлы должны быть разными.

Ошибки открытия, записи, сброса буфера вывода и закрытия файла должны диагностироваться. Порция считается успешно записанной только после успешного завершения файловых операций. До этого исходный буфер не очищается и статистика записанной порции не увеличивается. При ошибке обработка прекращается; архив может содержать частично записанную последнюю порцию, поэтому автоматический повтор дописывания запрещён.

В итоговой статистике выводятся:

- полученные сообщения — все прочитанные непустые строки;
- ошибочные сообщения;
- корректные события;
- отброшенные дубликаты успешно записанных порций;
- записи успешно записанных порций;
- остаток в буфере.

При нормальном завершении выполняются равенства:

- полученные сообщения = ошибочные сообщения + корректные события;
- корректные события = записанные записи + отброшенные дубликаты + остаток.

При аварийном завершении дополнительно указывается причина и состояние незавершённой порции; эти равенства не подменяют диагностику ошибки.

### Границы регламента

Каждая строка таблицы описывает отдельный запуск с корректным вводом и новым пустым архивом. N — число записей до удаления дубликатов, интервал — разность последней и первой метки текущего буфера. Если не указано иное, записи уникальны.

| Условие | Ожидаемый результат при конце файла |
|---|---|
| N = 29, интервал 60 минут | Архивации нет, остаток 29 |
| N = 30, интервал 59 минут | Архивации нет, остаток 30 |
| N = 30, интервал 60 минут | Одна порция, записано 30, остаток 0 |
| N = 31: первые 30 укладываются в 59 минут, последняя имеет интервал 60 минут | Одна порция, записано 31, остаток 0 |
| N = 30, интервал 75 минут | Одна порция, записано 30 |
| N = 30, интервал 0 минут | Архивации нет, остаток 30 |
| N = 30, интервал 60 минут, все ключи одинаковы | Записана первая запись, дубликатов 29 |
| N = 30, первая метка 23:30, последняя 00:30 следующего дня; остальные метки расположены между ними | Интервал 60 минут, записано 30 |

### Сравнение записей

Каждая пара проверяется независимо. Итоговая запись в архив возможна только в составе порции, выполнившей регламент.

| Первая запись | Вторая запись | Результат сравнения |
|---|---|---|
| 10:00 1 100 0 | 10:30 1 100 0 | Дубликат; сохраняется 10:00 |
| 10:00 1 100 0 | 10:00 1 100 0 | Дубликат |
| 10:00 1 100 0 | 10:30 2 100 0 | Разные записи: другой узел |
| 10:00 1 100 0 | 10:30 1 101 0 | Разные записи: другое число сообщений |
| 10:00 1 100 0 | 10:30 1 100 1 | Разные записи: другое число ошибок |

### Некорректный ввод

Каждая строка проверяется отдельно; после отклонения программа должна продолжить чтение следующей строки.

| Строка | Ожидаемый результат |
|---|---|
| 24:00 1 100 0 | Ошибка часов |
| 10:60 1 100 0 | Ошибка минут |
| 10:00 -1 100 0 | Отрицательный идентификатор |
| 10:00 1 -100 0 | Отрицательное количество сообщений |
| 10:00 1 100 -1 | Отрицательное количество ошибок |
| 10:00 1 100 | Недостаточно полей |
| 10:00 1 100 0 extra | Лишние данные |
| 10:00 1 1.5 0 | Дробное значение вместо целого |
| 10:00 2147483648 100 0 | Число вне диапазона |
| 10:00 999999999999999999999999 100 0 | Число вне диапазона, без переполнения при разборе |
| Пустая строка или строка из пробелов | Пропуск без увеличения счётчика сообщений |
| Непустая строка длиной 256 символов | Одна ошибка; продолжение строки не обрабатывается отдельно |

Граничные корректные записи: 00:00 0 0 0 и 23:59 2147483647 2147483647 2147483647.

Проверка восстановления после ошибки: файл из строк 10:00 1 100 0, 25:00 2 100 0, 10:01 3 100 0. Получено 3 сообщения, ошибочных 1, корректных 2, остаток 2; ошибочная метка 25:00 не изменяет временное состояние.

### Несколько порций и заполнение буфера

- Два последовательных набора по 30 уникальных записей: первый от 10:00 до 11:00, второй от 11:01 до 12:01. Ожидаются две порции по 30 записей и остаток 0. Между порциями нет общей точки отсчёта.
- Одинаковый ключ, встречающийся один раз в каждой из двух порций, сохраняется в обеих: фильтрация между порциями не выполняется.
- После полной порции добавлена одна запись в 11:05. При конце файла она остаётся в буфере; всего записано 30, остаток 1.
- Пустой входной файл: все счётчики равны 0, архивных порций нет.
- 1000 записей с меткой 10:00: буфер полон, интервал 0, архивации нет; при конце файла остаток 1000.
- После этих 1000 записей поступает 1001-я корректная запись в 10:01: ошибка переполнения, новая запись не добавляется, принудительной архивации нет.
- Первые 999 уникальных записей имеют метку 10:00, тысячная — 11:00: порция из 1000 записей архивируется, ошибки переполнения нет.

Для проверки ошибок файла отдельно следует использовать недоступный путь архива и ситуацию отказа записи. Ожидаются диагностика, аварийное завершение и отсутствие сообщения об успешной записи незавершённой порции.
