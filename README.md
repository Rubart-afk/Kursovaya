# Архив событий почтового сервера

Курсовой проект по дисциплине «Основы программирования и алгоритмизации». Индивидуальный вариант 11 «Почтовый сервер», уровень 1 (базовый).

## Постановка задачи

Разработать на C программу, которая читает текстовые сообщения о работе почтового сервера, накапливает события и записывает их в архив. Очередная порция отправляется в архив, когда между первой и последней записью прошло не менее 60 минут **и** в буфере накопилось не менее 30 записей. Перед записью из порции удаляются дубликаты. По итогам обработки выводится количество полученных сообщений, отброшенных дубликатов и архивных записей.

## Формат сообщения

Входной файл содержит по одному событию на строку. Например, строка `10:15 3 120 2` описывает событие в 10:15 для узла 3 со значениями 120 сообщений и 2 ошибки.

| Поле структуры `Event` | Значение |
|---|---|
| `h` | Час, от 0 до 23 |
| `m` | Минута, от 0 до 59 |
| `node` | Идентификатор узла |
| `messages` | Количество сообщений |
| `errors` | Количество ошибок |

Поля `node`, `messages` и `errors` принимают целые значения от 0 до 2147483647. Часы отделяются от минут двоеточием, остальные поля разделяются пробелами или табуляцией. Пробельные символы по краям строки допускаются. Максимальная длина строки без символов конца строки составляет 255 символов.

Пустые строки и строки из пробелов пропускаются. Для ошибочной строки выводятся её номер и причина. Такая строка не попадает в буфер и не влияет на расчёт времени. Ошибка чтения файла завершает обработку.

## Алгоритм обработки

1. Прочитать строку, проверить формат и добавить корректное событие в буфер.
2. Сравнить время добавленного события со временем первой записи в буфере. Проверить, что прошло не менее 60 минут и в буфере есть не менее 30 записей. В проверку входят все накопленные записи, включая дубликаты и только что добавленное событие.
3. Если оба условия выполнены, сравнить записи по полям `node`, `messages` и `errors`. Для каждого сочетания сохранить первую запись с её временем. Порядок оставшихся записей сохраняется.
4. Дописать порцию в архив. После успешной записи очистить буфер. Следующий интервал начинается с первого нового события.

Входные события расположены в хронологическом порядке. Промежуток между соседними событиями меньше суток. Если время следующего корректного события меньше предыдущего, оно относится к следующим суткам. Например, от 23:30 до 00:30 проходит 60 минут. Одинаковые метки относятся к одному моменту. Без даты нельзя отличить переход через полночь от нарушения порядка строк.

Буфер вмещает 1000 записей. Если очередное корректное событие не помещается в буфер, обработка останавливается с сообщением об ошибке. При обычном конце файла незавершённая порция остаётся неархивированной. В статистике указывается её размер.

## Архив и статистика

Порции дописываются в один текстовый файл. Каждая строка имеет формат `HH:MM node messages errors`. Дубликаты проверяются внутри одной порции. Повторная обработка того же файла дописывает записи заново. Входной и архивный файлы используются отдельно.

При ошибке файловой операции обработка прекращается. Если в файл успела попасть часть порции, эта порция не учитывается в статистике успешной записи.

В число полученных сообщений входят все прочитанные непустые строки. Отдельно подсчитываются корректные и ошибочные сообщения, отброшенные дубликаты, записанные события и остаток. При обычном завершении количество корректных событий равно сумме записанных, отброшенных как дубликаты и оставшихся в буфере.

### Границы регламента

Каждая строка таблицы описывает отдельный запуск с корректным вводом и новым пустым архивом. N — число записей до удаления дубликатов, интервал — разность последней и первой метки текущего буфера. Если не указано иное, записи уникальны.

| Условие | Ожидаемый результат при конце файла |
|---|---|
| N = 29, интервал 60 минут | Архивации нет, остаток 29 |
| N = 30, интервал 59 минут | Архивации нет, остаток 30 |
| N = 30, интервал 60 минут | Одна порция, записано 30, остаток 0 |
| N = 31: первые 30 укладываются в 59 минут, последняя имеет интервал 60 минут | Одна порция, записано 31, остаток 0 |
| N = 30, интервал 75 минут | Одна порция, записано 30 |
| N = 30, интервал 0 минут | Архивации нет, остаток 30 |
| N = 30, интервал 60 минут, все ключи одинаковы | Записана первая запись, дубликатов 29 |
| N = 30, первая метка 23:30, последняя 00:30 следующего дня; остальные метки расположены между ними | Интервал 60 минут, записано 30 |

### Сравнение записей

Каждая пара проверяется независимо. Итоговая запись в архив возможна только в составе порции, выполнившей регламент.

| Первая запись | Вторая запись | Результат сравнения |
|---|---|---|
| 10:00 1 100 0 | 10:30 1 100 0 | Дубликат; сохраняется 10:00 |
| 10:00 1 100 0 | 10:00 1 100 0 | Дубликат |
| 10:00 1 100 0 | 10:30 2 100 0 | Разные записи: другой узел |
| 10:00 1 100 0 | 10:30 1 101 0 | Разные записи: другое число сообщений |
| 10:00 1 100 0 | 10:30 1 100 1 | Разные записи: другое число ошибок |

### Некорректный ввод

Каждая строка проверяется отдельно; после отклонения чтение продолжается со следующей строки.

| Строка | Ожидаемый результат |
|---|---|
| 24:00 1 100 0 | Ошибка часов |
| 10:60 1 100 0 | Ошибка минут |
| 10:00 -1 100 0 | Отрицательный идентификатор |
| 10:00 1 -100 0 | Отрицательное количество сообщений |
| 10:00 1 100 -1 | Отрицательное количество ошибок |
| 10:00 1 100 | Недостаточно полей |
| 10:00 1 100 0 extra | Лишние данные |
| 10:00 1 1.5 0 | Дробное значение вместо целого |
| 10:00 2147483648 100 0 | Число вне диапазона |
| 10:00 999999999999999999999999 100 0 | Число вне диапазона, без переполнения при разборе |
| Пустая строка или строка из пробелов | Пропуск без увеличения счётчика сообщений |
| Непустая строка длиной 256 символов | Одна ошибка; продолжение строки не обрабатывается отдельно |

Граничные корректные записи: 00:00 0 0 0 и 23:59 2147483647 2147483647 2147483647.

Проверка восстановления после ошибки: файл из строк 10:00 1 100 0, 25:00 2 100 0, 10:01 3 100 0. Получено 3 сообщения, ошибочных 1, корректных 2, остаток 2; ошибочная метка 25:00 не изменяет временное состояние.

### Несколько порций и заполнение буфера

- Два последовательных набора по 30 уникальных записей: первый от 10:00 до 11:00, второй от 11:01 до 12:01. Ожидаются две порции по 30 записей и остаток 0. Между порциями нет общей точки отсчёта.
- Одинаковый ключ, встречающийся один раз в каждой из двух порций, сохраняется в обеих: фильтрация между порциями не выполняется.
- После полной порции добавлена одна запись в 11:05. При конце файла она остаётся в буфере; всего записано 30, остаток 1.
- Пустой входной файл: все счётчики равны 0, архивных порций нет.
- 1000 записей с меткой 10:00: буфер полон, интервал 0, архивации нет; при конце файла остаток 1000.
- После этих 1000 записей поступает 1001-я корректная запись в 10:01: ошибка переполнения, новая запись не добавляется, принудительной архивации нет.
- Первые 999 уникальных записей имеют метку 10:00, тысячная — 11:00: порция из 1000 записей архивируется, ошибки переполнения нет.

При недоступном пути архива или отказе записи ожидается сообщение об ошибке. Незавершённая порция не учитывается как успешно записанная.
