# Архив событий почтового сервера

Курсовой проект по дисциплине «Основы программирования и алгоритмизации».

**Индивидуальный вариант: 11. Почтовый сервер. Уровень: 1 — базовый.**

## Назначение проекта

Программа на языке C предназначена для обработки текстовых сообщений о работе почтового сервера. Каждое сообщение преобразуется в запись структуры Event. Записи накапливаются в оперативном буфере, а при выполнении регламента обрабатываются и записываются в архивный файл.

## Условия индивидуального варианта

- Формат сообщения: `час:минута node messages errors`.
- Структура Event: `h, m, node, messages, errors` — не более пяти полей.
- Регламент архивации: через 60 минут **и** при наличии не менее 30 записей.
- Запись считается дубликатом, если совпадают все поля, кроме времени.
- Дополнительный поиск не требуется.
- Дополнительная сортировка не требуется.
- Необходимо вывести количество полученных, отброшенных как дубликаты и записанных в архив записей.

## Входные данные

Пример строки:

```text
10:15 3 120 2
```

| Поле | Назначение |
|---|---|
| h | Часы |
| m | Минуты |
| node | Идентификатор узла |
| messages | Числовой показатель количества сообщений |
| errors | Числовой показатель количества ошибок |

Период, к которому относятся показатели messages и errors, в задании не уточнён. Программа должна обрабатывать переданные значения без предположений об их накопительном характере.

## Правила обработки

1. Прочитать строку и разобрать поля с помощью scanf или sscanf.
2. Проверить корректность данных.
3. Добавить запись в массив структур.
4. Проверить одновременное выполнение двух условий: прошло не менее 60 минут и накоплено не менее 30 записей.
5. При выполнении регламента удалить дубликаты из накопленного набора.
6. Записать обработанные записи в файл.
7. После успешной записи очистить оперативный буфер и начать следующий период.

Временной интервал определяется по временным меткам сообщений, а не ожиданием реального времени. Порог количества проверяется до удаления дубликатов.

Например, записи `10:15 3 120 2` и `10:40 3 120 2` считаются дубликатами. Запись `10:45 3 121 2` отличается показателем messages и дубликатом этих записей не является.

## Решения, требующие уточнения

До реализации соответствующих этапов необходимо определить:

- точку отсчёта интервала архивации;
- обработку перехода через полночь и сообщений с нарушенным порядком времени;
- поведение при завершении входного потока до выполнения регламента;
- поведение при заполнении массива до выполнения регламента;
- выбор сохраняемой записи среди дубликатов;
- способ хранения нескольких архивных периодов.

Эти вопросы не изменяют условия варианта; принятые решения будут явно описаны и проверены.

## Требования к исходному коду

- Используется язык C.
- Объявления функций располагаются до main либо в заголовочном файле.
- Определения функций располагаются после main либо в соответствующем файле реализации.
- Кириллица должна корректно отображаться в исходниках и при запуске.
- Основная логика выделяется в функции с явными параметрами и результатами.
- Входные данные, границы массивов и ошибки файловых операций проверяются.
